# 🦸 AvengersCardGame

Telegram-бот на Java, в котором пользователи раз в день получают карточки мстителей разной редкости. Карточки можно разбирать на «кусочки», крафтить из них новые, продавать и покупать, а также сражаться друг с другом.

**Авторы:** Григорян Нарек, Проскурнин Георгий

---

## 📌 Этапы разработки

### Задача 1. Фундамент: бот, БД и базовые функции

**Цель:** рабочий Telegram-бот с сохранением пользователей.

#### Команды

- `/start` — бот выводит приветственное сообщение, регистрация игрока при первом вызове.
- `/profile` — вывод имени, описания профиля, баланса и количества карточек.
- `/help` — вывод команд бота и их описание.
- `/setname <name>` — пользователь может изменить отображаемое для других игроков имя в боте. Имя Telegram-аккаунта — имя по умолчанию. Максимум 128 символов латиницей.
- `/setbio <bio>` — пользователь может добавить короткое описание своего профиля. Максимум 256 символов латиницей или кириллицей + эмодзи и знаков препинания, пробелов, цифр, спецсимволы (/|\<>@#$%^&*(){}[]`~;:'"-_=+).
- Неизвестная команда — бот выводит сообщение о неизвестной команде и вызывает `/help`.

**Важно:** информация сохраняется при перезапусках бота.

### Задача 2. Карточки и ежедневная выдача

## 📌 Этапы разработки

**Цель:** игровая механика получения карточек.

#### Основные компоненты

- **Справочник карточек мстителей** — `Hero`, `HeroRarity`, шансы выпадения.
- **Система редкостей** — Common / Rare / Epic / Legendary.
- **Команды** `/daily` и `/inventory`.
- **Оформление карточек** — эмодзи, ATK / DEF / HP.
- **Уведомление** об окончании кулдауна `/daily`.

#### Система редкостей

| Редкость | Вес | Шанс выпадения | Эмодзи |
|---|---|---|---|
| Common | 60 | 60% | ⚪ |
| Rare | 25 | 25% | 🔵 |
| Epic | 12 | 12% | 🟣 |
| Legendary | 3 | 3% | 🟡 |

Сумма весов равна 100, поэтому вес совпадает с шансом в процентах. При выдаче сначала выбирается редкость по весам, затем случайный герой этой редкости.

#### Справочник карточек

- `id` — уникальный идентификатор.
- `name` — имя героя (например, Iron Man).
- `rarity` — редкость (`HeroRarity`).
- `atk` — атака.
- `def` — защита.
- `hp` — здоровье.
- `description` — короткое описание (опционально).
- `imageUrl` / `fileId` — изображение карточки (опционально).

`HeroRarity` — перечисление: `COMMON`, `RARE`, `EPIC`, `LEGENDARY`.

Справочник наполняется при первом запуске (seed) и не должен дублироваться при перезапусках бота.

#### Команды

- `/daily` — раз в 24 часа выдаёт от 1 до 3 карточек.
  - Количество карточек выбирается случайно: 1, 2 или 3.
  - Каждая карточка выбирается независимо по весам редкостей.
  - Время последнего получения хранится в поле `lastDailyAt` пользователя.
  - Если с последнего получения прошло меньше 24 часов, бот сообщает, сколько осталось ждать.
  - Время сохраняется в БД и не сбрасывается при перезапуске бота.
- `/inventory` — показывает список карточек игрока с inline-кнопками.
  - Карточки отображаются списком, одинаковые карточки группируются (например, `×3`).
  - Inline-кнопки: просмотр конкретной карточки, переход между страницами (пагинация).
  - Если коллекция пуста, бот предлагает воспользоваться `/daily`.
- Обновить `/help` — добавить описание `/daily` и `/inventory`.
- Обновить `/profile` — количество карточек должно считаться по реальной коллекции.

#### Оформление карточек

Каждая карточка отображается в едином формате:
🟣 Iron Man [Epic]
⚔️ ATK: 85
🛡 DEF: 70
❤️ HP: 120


Эмодзи редкости: ⚪ Common, 🔵 Rare, 🟣 Epic, 🟡 Legendary.

#### Уведомление о кулдауне

- Когда с момента последнего `/daily` проходит 24 часа, бот отправляет игроку сообщение о том, что награда снова доступна.
- Уведомление отправляется один раз за цикл.
- Реализуется фоновой задачей (планировщик), которая периодически проверяет `lastDailyAt`.
- Планировщик должен корректно работать после перезапуска бота: незавершённые уведомления определяются по данным из БД.
- Если пользователь заблокировал бота, ошибка отправки не должна ронять задачу.

## Задача 3. Экономика: разбор, крафт, продажа, покупка

📌 **Этапы разработки**

**Цель:** цикл оборота ресурсов. Карточки превращаются в «кусочки», из кусочков крафтятся новые карточки, а лишние карточки можно продать другим игрокам за внутриигровую валюту.

---

### Основные компоненты

- Валюта — 💎 (баланс игрока хранится в БД). Название и эмодзи валюты задаются в конфигурации, в коде и сообщениях бота они не зашиваются. В сообщениях для игрока используется только эмодзи.
- Ресурс — **кусочки** 🧩 (хранятся отдельно от карточек).
- Команды `/disassemble`, `/craft`, `/sell`, `/market`.
- Все действия выполняются через **inline-кнопки**, аргументы в командах не нужны.
- Рынок — общий список лотов, созданных игроками.
- Атомарность операций: списание и начисление ресурсов происходят в одной транзакции.

---

### Разбор карточек

При разборе карточка удаляется из коллекции, а игрок получает кусочки. Количество кусочков зависит от редкости.

| Редкость  | Эмодзи | Кусочков за разбор | Кусочков для крафта |
|-----------|--------|--------------------|---------------------|
| Common    | ⚪     | 1                  | 5                   |
| Rare      | 🔵     | 3                  | 15                  |
| Epic      | 🟣     | 8                  | 40                  |
| Legendary | 🟡     | 20                 | 100                 |

Кусочки универсальные: хранится общий баланс, а не отдельный по каждому герою.

**Сценарий:**

1. `/disassemble` показывает коллекцию игрока (список с пагинацией, как в `/inventory`) и кнопки выбора карточки.
2. После выбора карточки бот предлагает количество кнопками: `1`, `5`, `Все`.
3. Бот просит подтвердить действие кнопками `Подтвердить` / `Отмена`.

---

### Крафт

- Игрок выбирает **редкость** кнопкой, а не конкретного героя.
- За кусочки списывается стоимость крафта, после чего игрок получает **случайного героя** выбранной редкости.
- На кнопках указана стоимость крафта. Если кусочков не хватает, нажатие на кнопку показывает, сколько ещё нужно.
- Крафт и списание кусочков выполняются в одной транзакции: при ошибке ничего не списывается.

---

### Рынок

- Игрок выставляет карточку на продажу за указанную цену.
- Выставленная карточка **резервируется** и пропадает из `/inventory`, пока лот активен.
- Другой игрок покупает лот: валюта списывается у покупателя, начисляется продавцу (за вычетом комиссии 5%), карточка переходит покупателю.
- Свой лот купить нельзя.
- Лот можно снять с продажи, карточка возвращается в коллекцию.
- Одну и ту же карточку нельзя продать дважды, а один лот нельзя купить двумя игроками одновременно (защита от гонок).

**Ограничения цены:**

| Редкость  | Минимум | Максимум |
|-----------|---------|----------|
| Common    | 10      | 200      |
| Rare      | 50      | 1000     |
| Epic      | 200     | 5000     |
| Legendary | 1000    | 25000    |

**Сценарий продажи:**

1. `/sell` показывает коллекцию игрока с кнопками выбора карточки.
2. После выбора карточки бот предлагает цену кнопками: `Минимум`, `Средняя`, `Максимум`.
3. Бот просит подтвердить выставление лота кнопками `Подтвердить` / `Отмена`.

**Сценарий покупки и снятия:**

- В `/market` у каждого лота есть кнопка `Купить`, покупка подтверждается кнопкой.
- В `/market` есть кнопка `Мои лоты`, в ней у каждого своего лота есть кнопка `Снять`.

---

### Команды

- `/disassemble` — открыть выбор карточек для разбора на кусочки.
- `/craft` — открыть выбор редкости для крафта.
- `/sell` — открыть выбор карточки для продажи.
- `/market` — показать активные лоты с inline-кнопками и пагинацией. Кнопки: фильтр по редкости, `Купить`, `Мои лоты`.
- **Обновить `/help`** — добавить описание новых команд.
- **Обновить `/profile`** — показывать баланс валюты и кусочков.

---

### Правила и валидация

- Нельзя разобрать или продать карточку, которой нет в коллекции.
- Нельзя разобрать карточку, выставленную на рынок.
- Цена должна быть целым положительным числом в допустимых пределах.
- Нельзя купить лот, если не хватает валюты.
- Нельзя купить уже проданный или снятый лот.
- Устаревшие кнопки (например, на карточку, которой уже нет) обрабатываются корректно: бот сообщает об ошибке и не меняет данные.
- Все балансы (валюта, кусочки) не могут уходить в минус.
- Все данные (баланс, кусочки, лоты) сохраняются в БД и не теряются при перезапуске бота.

**Результат:** игроки разбирают лишние карточки, крафтят нужные и торгуют друг с другом через удобные кнопки. Экономика замкнута, балансы корректны и сохраняются при перезапусках.

# Задача 4. Сражения (PvP) и промокоды

📌 **Этапы разработки**

**Цель:** игрок собирает колоду из трёх карточек и сражается с колодами других игроков. За бои игрок получает 💎 и рейтинг: это основной источник внутриигровой валюты, на которую покупаются лоты на рынке. Дополнительный источник наград — промокоды, которые раздают администраторы.

---

## Основные компоненты

- **Колода** — 3 карточки из коллекции игрока, порядок важен (слоты 1–3).
- **Бой** — автоматический расчёт трёх раундов (дуэль «слот против слота»), без участия игроков в процессе.
- **Асинхронность** — соперник не обязан быть онлайн: бой идёт против его текущей колоды, о результате он получает уведомление.
- **Бои с ботами** — три уровня сложности (PvE). Нужны, чтобы игрок мог зарабатывать 💎 и тренировать колоду, даже когда нет подходящих соперников.
- **Награды** — 💎 за бои и рейтинг. Размеры наград, лимиты и параметры задаются в конфигурации, в коде не зашиваются.
- **Промокоды** — наборы наград за код; создаются администраторами.
- **Команды** `/deck`, `/battle`, `/top`, `/promo`.
- Все действия выполняются через **inline-кнопки**, аргументы в командах не нужны (кроме `/promo <code>` и админских команд).
- **Атомарность:** начисление награды и изменение рейтинга происходят в одной транзакции.
- **Защита от двойных нажатий:** повторное нажатие не создаёт второй бой.

---

## Колода

- В колоде ровно 3 слота. Бой без полной колоды невозможен.
- В колоду можно поставить только карточки из коллекции игрока.
- Одного и того же героя можно поставить в несколько слотов, только если в коллекции хватает копий (например, для двух слотов нужен `×2`).
- Карточка, выставленная на рынок, в колоду попасть не может.
- Карточку, которая нужна колоде, нельзя разобрать (`/disassemble`) и продать (`/sell`), пока она стоит в слоте. Бот предлагает сначала убрать её из колоды. Если у игрока есть лишние копии сверх тех, что стоят в колоде, их можно разбирать и продавать.
- Колода сохраняется в БД и не теряется при перезапуске бота.

---

## Правила боя

Бой состоит из **3 раундов**. В раунде `i` встречаются карточка слота `i` атакующего и карточка слота `i` защищающегося. Побеждает тот, кто выиграл больше раундов (ничьей не бывает).

**Дуэль в раунде:**

1. Первой бьёт карточка с большим `ATK`. При равенстве первой бьёт карточка атакующего.
2. Карточки бьют по очереди, пока у одной из них `HP` не станет ≤ 0.
3. Урон за удар: `max(1, ATK атакующей − DEF защищающейся / 2)`, деление целочисленное.
4. С вероятностью 10% удар критический: урон ×1.5 (округление вниз). Шанс и множитель задаются в конфигурации.
5. Раунд выигрывает карточка, оставшаяся в живых. `HP` в раундах не переносится: каждая дуэль начинается с полным здоровьем.

Генератор случайных чисел внедряется через зависимость, чтобы бой можно было покрыть детерминированными тестами.

В сообщении о бое показываются только участники раунда и победитель. Детальный лог ударов не выводится.

## Награды и рейтинг

| Исход | 💎 | Рейтинг |
|---|---|---|
| Победа атакующего | 100 | +25 |
| Поражение атакующего | 20 | −15 |
| Победа защищающегося (соперник напал и проиграл) | 30 | +10 |
| Поражение защищающегося | 0 | 0 |

- Начальный рейтинг — 1000, ниже 0 рейтинг не опускается.
- **Лимит наград PvP:** 💎 за атаки на игроков начисляются за первые 10 атак в сутки. Поражение атакующего тоже расходует слот. Бои сверх лимита разрешены, но дают только изменение рейтинга. Награда защищающегося в лимит не входит.
- **Сутки** считаются по UTC. Начало суток задаётся в конфигурации: `BATTLE_DAY_START_HOUR` — целое от 0 до 23, по умолчанию 0.
- Часового лимита на соперника и кулдауна между боями нет.
- Нападать на самого себя нельзя.
- Поражение защищающегося ничего у него не отнимает, поэтому игрока нельзя «выжать» чужими атаками.
- **Победы и поражения** считаются только за PvP: атаки и защиты. Бои с ботами в статистику не входят.

---

## Бои с ботами

Бот — это не игрок, а сгенерированная колода из трёх героев справочника. Бой идёт по тем же правилам, что и бой с игроком.

| Уровень | Имя бота | Диапазон редкостей | Награда за победу | Награда за поражение |
|---|---|---|---|---|
| Лёгкий | Рядовой Гидры | Common–Rare | 15 💎 | 0 |
| Средний | Капитан Гидры | Rare–Epic | 30 💎 | 0 |
| Сложный | Красный Череп | Epic–Legendary | 60 💎 | 0 |

- Колода бота формируется заново перед каждым боем: каждый слот независимо получает случайного героя из допустимого диапазона редкостей. Один и тот же герой в колоде бота может повторяться.
- Бой с ботом **не меняет рейтинг** и не попадает в `/top`, поэтому на нём нельзя накрутить рейтинг.
- **Лимит наград:** награды за победу над ботами начисляются за первые 5 награждённых побед в сутки. Поражение и победа сверх лимита счётчик не расходуют. Лимит не зависит от лимита боёв с игроками. Сутки считаются так же, как для PvP.
- Бот награду не получает и никого не уведомляет.
- Уровни, диапазоны редкостей, имена ботов, награды и лимит задаются в конфигурации, в коде не зашиваются.
- Для баланса: максимум 💎 в сутки за свои атаки на игроков и бои с ботами — 10 × 100 + 5 × 60 = 1300 (не считая наград за успешную защиту). Для сравнения, цена лота Epic на рынке — от 200 до 5000 💎.

---

## Команды

- `/deck` — показать колоду и открыть её редактирование.
- `/battle` — начать бой. Кнопки: `Бой с ботом`, `Случайный соперник`, `Выбрать соперника`.
  - **Бой с ботом:** выбор уровня кнопками `Лёгкий`, `Средний`, `Сложный`. На кнопке указана награда за победу и сколько побед с наградой осталось сегодня. При нажатии показывается экран подтверждения с актуальной наградой и остатком лимита; бой начинается только после подтверждения.
  - **Случайный соперник:** равновероятно выбирается игрок с полной колодой, кроме самого игрока. Если подходящих игроков нет, бот сообщает: «Нет доступных соперников. Попробуй бой с ботом.»
  - **Выбрать соперника:** список игроков с полной колодой, пагинация, кнопка на каждого игрока. В списке показываются имя и рейтинг. Сортировка — по рейтингу по убыванию.
- `/top` — топ-3 игроков по рейтингу и место самого игрока.
- `/promo <code>` — активировать промокод.
- `/promo_create`, `/promo_list` — только для администраторов.
- **Обновить `/help`** — добавить описание новых команд. Админские команды показываются в `/help` только администраторам.
- **Обновить `/profile`** — показывать рейтинг, победы и поражения.

---

## Правила и валидация

- Нельзя начать бой с неполной колодой.
- Нельзя выбрать соперника без полной колоды, а также самого себя.
- Бой с ботом тоже требует полной колоды из 3 карточек.
- При нажатии на уровень бота бот всегда показывает актуальные условия (награду и остаток лимита) и не начинает бой без подтверждения.
- При нажатии на соперника бот перечитывает его колоду. Если колода полная — бой идёт против текущей колоды. Если неполная — ошибка, данные не меняются.
- При нажатии на карточку в колоде бот перечитывает доступные копии. Если карточка уже недоступна — ошибка, слот не меняется.
- Нельзя поставить в колоду карточку, которой нет в коллекции, или карточку, выставленную на рынок.
- Повторное нажатие на кнопку боя не создаёт второй бой. Пока бой обрабатывается, повторный запрос получает сообщение «Бой уже обрабатывается» и не создаёт второй бой.
- Если соперник заблокировал бота, ошибка отправки уведомления не должна ронять бой и не отменяет его результат.
- Все балансы и рейтинг не могут уходить в минус.
- Все данные (колода, рейтинг, награды, победы/поражения, счётчики боёв за сутки) сохраняются в БД и не теряются при перезапуске бота.

## Промокоды

Игрок может получить награду по промокоду. Это одна награда или набор наград: валюта, кусочки, конкретные герои, случайные герои заданной редкости. Промокоды создают администраторы бота.

### Основные компоненты

- **Промокод** — слово из латиницы, цифр и `_` длиной от 4 до 32 символов, регистр не важен. Каждый промокод уникален. Хранится в верхнем регистре.
- **Набор наград** — награды могут быть разных типов и повторяться: например, `500 💎 + 20 🧩 + Thor + Iron Man`, или два разных героя, или три случайных Epic.
- **Типы наград:** 💎 (`gems`), кусочки 🧩 (`shards`), конкретный герой (`hero`), случайный герой заданной редкости (`rarity`). Набор типов фиксирован.
- **Условия:** срок действия и ограничение на общее число активаций относятся к промокоду целиком, а не к отдельным наградам. Администратор может отключить промокод.
- **Активация** — команда `/promo <code>`. Отдельной кнопки в `/market` нет.
- **Администраторы** создают и отключают промокоды командами `/promo_create` и `/promo_list`. Для остальных игроков этих команд нет: бот отвечает как на неизвестную команду.
- В сообщениях для игрока используется только эмодзи валюты.

### Модель наград

- Каждый тип награды имеет собственные параметры: для `gems` и `shards` — количество, для `hero` — герой из справочника, для `rarity` — одна из допустимых редкостей.
- Поддерживаются ровно четыре типа: `gems`, `shards`, `hero`, `rarity`.
- Для случайных наград сохраняется **фактический результат** (какие карточки выпали) в БД для аудита. Отдельной команды просмотра нет.

### Активация

1. Игрок вводит `/promo <code>`.
2. Бот проверяет код и, если всё в порядке, выдаёт **все** награды и сообщает о каждой.

### Команды

- `/promo <code>` — активировать промокод.
- `/promo_create <code> <limit> <expires> <reward> [<reward> ...]` — создать промокод (только для администраторов).
  - `limit`: сколько раз промокод можно активировать всего, `0` — без ограничения.
  - `expires`: последний день действия в формате `ГГГГ-ММ-ДД`, `0` — бессрочно. Последний день включительно.
  - `reward`: награда в формате `тип:значение`. Можно указать несколько наград через пробел (не больше 10), типы можно смешивать и повторять:
    - `gems:<количество>` — 💎;
    - `shards:<количество>` — кусочки 🧩;
    - `hero:<номер героя>` — конкретный герой (один экземпляр). Чтобы выдать нескольких героев, укажите несколько `hero:`. Повтор одного номера выдаёт несколько копий;
    - `rarity:<редкость>` — случайный герой заданной редкости (`common`, `rare`, `epic`, `legendary`). Повтор выдаёт несколько случайных карточек, каждая выбирается независимо.
- `/promo_list` — список промокодов с inline-кнопками и пагинацией (только для администраторов). В строке показывается краткий состав наград (если не помещается, сокращается), число активаций, срок и статус. Кнопки: `Отключить` / `Включить`. Отключённые и истёкшие промокоды показываются со статусом.
- **Обновить `/help`** — упомянуть, что промокод вводится командой `/promo <code>`. Админские команды показываются в `/help` только администраторам, с описанием формата наград.

### Правила и валидация

- Промокод должен существовать, быть включённым, не истёкшим и не исчерпанным.
- Один игрок может активировать один и тот же промокод только один раз, независимо от числа наград в нём.
- Промокод нельзя активировать больше раз, чем разрешено, даже если его вводят несколько игроков одновременно.
- Нельзя создать промокод, который уже существует.
- Промокод создаётся целиком или не создаётся вовсе: если хотя бы одна награда некорректна, не сохраняется ни промокод, ни остальные награды. Бот указывает, какая именно награда неверна.
- Должна быть хотя бы одна награда, но не больше 10.
- Количество для `gems` и `shards` — целое число больше 0. Герой для награды должен существовать, редкость должна быть одной из четырёх. Неизвестный тип награды отклоняется.
- Награды выдаются по принципу «всё или ничего». Если не удалось выдать хотя бы одну (например, героя убрали из справочника), игрок не получает ничего, активация не засчитывается, а игрок видит сообщение об ошибке.
- Карточки из промокода попадают в коллекцию, как при `/daily`. Для случайного героя редкость выбирается так же, как при крафте.
- Блокировки за неверные попытки ввода нет.
- Все данные (промокоды, награды, активации, результаты случайных наград) сохраняются и не теряются при перезапуске бота.

Боты помогают зарабатывать и тренироваться, даже когда нет подходящих соперников. Экономика замыкается: карточки превращаются в силу в бою, бои дают валюту, валюта идёт на покупки на рынке. Дополнительный источник наград — промокоды, которые раздают администраторы. Все балансы корректны и сохраняются при перезапусках.
