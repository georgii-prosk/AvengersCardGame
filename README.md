# 🦸 AvengersCardGame

Telegram-бот на Java, в котором пользователи раз в день получают карточки мстителей разной редкости. Карточки можно разбирать на «кусочки», крафтить из них новые, продавать и покупать, а также сражаться друг с другом.

**Авторы:** Григорян Нарек, Проскурнин Георгий

---

## 📌 Этапы разработки

### Этап 1. Фундамент: бот, БД и базовые сущности

**Цель:** рабочий Telegram-бот с сохранением пользователей.

- Сущности: `User`, `Card`, `Rarity`, `Inventory`.
- Команда `/start` — регистрация игрока в БД.
- Команда `/profile` — вывод баланса и количества карточек.
- Логирование (`slf4j`), конфиг через `application.yml` (токен в ENV).
- `docker-compose` с БД для локальной разработки.

**Результат:** бот отвечает, пользователи сохраняются, есть каркас проекта.

---

### Этап 2. Карточки и ежедневная выдача

**Цель:** игровая механика получения карточек.

- Справочник карточек мстителей (`Hero`, `HeroRarity`, шансы выпадения).
- Система редкостей: **Common / Rare / Epic / Legendary** (веса: 60 / 25 / 12 / 3).
- Команда `/daily` — раз в 24 часа выдача 1–3 карточек (проверка `lastDailyAt`).
- Команда `/inventory` — список карточек с inline-кнопками.
- Красивые подписи карточек (эмодзи, ATK / DEF / HP).
- Уведомление, когда кулдаун `/daily` истёк.

**Результат:** игрок заходит раз в день и получает карточки.

---

### Этап 3. Экономика: разбор, крафт, продажа, покупка

**Цель:** цикл оборота ресурсов.

- Сущности: `Shard` (кусочки), `Market` (лоты), `Transaction`.
- Команда `/dismantle <id>` — разбор карточки на кусочки (кол-во зависит от редкости).
- Команда `/craft` — сборка карточки из кусочков (например, 10 Rare-кусочков → 1 Rare-карточка).
- Команда `/sell <id> <price>` — выставление на рынок.
- Команда `/market` — список лотов с фильтрами (по редкости, цене, герою).
- Команда `/buy <lotId>` — покупка (атомарная транзакция: списание / начисление баланса, передача карточки).
- Внутренняя валюта: **«щиты»**.

**Результат:** полноценная внутриигровая экономика.

---

### Этап 4. Сражения (PvP)

**Цель:** боевая система между игроками.

- Модель боя: `Battle`, `BattleLog`, `BattleResult`.
- Формат: 3 карточки vs 3 карточки (колода).
- Расчёт: ATK / DEF + рандом ±10%, пошаговые раунды до победы одной из сторон.
- Команды:
  - `/battle @username` — вызов (inline-кнопка «Принять»).
  - `/deck` — сборка боевой колоды.
- Награды: победитель забирает часть валюты проигравшего (ставка), рейтинг ELO.
- Кулдаун на бои (например, 30 мин), чтобы не абьюзили.
- Отправка анимированного лога боя (последовательные сообщения или `editMessage`).

**Результат:** игроки соревнуются друг с другом.

---

### Этап 5. Полировка, баланс и запуск

**Цель:** стабильный и приятный продукт.

- **Админка:** команды `/give`, `/ban`, `/stats` для админов.
- **Балансировка:** выпадение, цены крафта, урон, награды — на основе аналитики.
- **Античит:** защита от двойного `/daily`, гонок при покупке (оптимистичные локи).
- **Уведомления:** напоминания про `/daily`, окончание боя, продажа лота.
- **UX:** inline-меню вместо набора команд, эмодзи, кастомные стикеры.
- **Метрики:** DAU, средний баланс, топ-карточки (Grafana / Prometheus или SQL-отчёты).
- **Деплой:** Docker → VPS (Timeweb / Selectel), автозапуск через `systemd`, бэкапы БД.
- **Фикс багов.**

**Результат:** релиз и первые живые игроки.
